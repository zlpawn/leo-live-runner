# 硬件型号档案：HJ07 智能门锁

## 1. 硬件与软件栈概览

| 维度 | 规格 |
| :--- | :--- |
| **主控 MCU** | Nordic nRF54L15（ARM Cortex-M33） |
| **RTOS** | Zephyr RTOS v4.4.0（MCUboot 引导后偏移 `0x8800`） |
| **通信模组** | Eigencomm Cat.1（UART `0x400C6000` AT 串口） |
| **Product / Model ID** | `0x0c74`（十进制 `3188`，产品名 `_hj07_`） |
| **默认协议端口** | TCP `8010`（二进制 `0xBE` 帧格式） |

---

## 2. 内存注入与分区关键偏移

| 用途 | 地址 | 说明 |
| :--- | :--- | :--- |
| **VectorTableOffset** | `0x00008800` | 应用中断向量表基址，`SP` 在 `+0x0`，`Reset_Handler (PC)` 在 `+0x4` |
| **工厂 IMEI (RRAM)** | `0x0007ea00` | NUL 结尾的 15 位 ASCII 字符串，启动时优先于 `AT+CGSN` 被读取 |
| **设备状态区 (RRAM)** | `0x0007ea40` | 存储 `reg_rst` / `plat_rst` / `setup_rst` / `touch_lvl` 等状态位，**不要把 `localkey` 写入此区**，否则会破坏 `store_interface` 状态机 |
| **Localkey 缓冲 (SRAM)** | `0x200084c6` | 16 字节 AES-128 密钥区；由于 Zephyr 启动阶段会清零 BSS，需在 GRTC tick 中持续保活写入；固件校检 `key[0] != 0 && key[15] != 0` 后将其指针写入 `0x20004e68` |

---

## 3. 端云鉴权与协议关键细节

1. **密钥拼接规则（极易踩坑）**：
   - 后端库 `iot_plat.lock_hardware_info.tk_key` 通常为 16 个十六进制字符（8 字节，如 `0011223344556677`）。
   - 云端鉴权拼接 `tkKey + tkKey` 为 32 位十六进制字符串，经 `Ascii2Hex` 转成 **16 字节二进制密钥** 做 `AES-128-ECB`。
   - 对应地，固件侧 `0x200084c6` 需注入这 8 字节十六进制重复两遍后的 **16 字节原始字节**（日志会打印 `###localkey:<前8字节小写hex>`）。
2. **时间戳同步规则（防重放与时区）**：
   - Eigencomm `AT+ZZCCLK` 返回格式为 `YYMMDDHHMMSS`（12 位数字），且固件内部会**减去 `0x7080`（28800 秒 / 8 小时）**以转为 UTC Epoch 时间戳。
   - 因此仿真模组必须返回**当前北京时间（UTC+8 / 本地时间）**，既不能写死历史日期，也不能直接填 UTC 时间，否则后端防重放校验会拒绝。
3. **关键上下行帧类型**：
   - `0x8001` -> `0x0002`：鉴权请求与响应（固件打印 `Auth Pass`）
   - `0x8005` -> `0x0004`：门锁主动拉取平台下发指令 / 平台推送控制指令
   - `0x8108`：设备状态事件主动上报（电量 `bat`、锁状态、时间戳 TLV）
   - `0xFFFE...`：OTA 相关上报帧
