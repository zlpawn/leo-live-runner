Leo Live Inspector · 测试环境控制台

仅测试环境 · 生产只读

这个控制台能做什么

本页面是 leo-live-inspector 的独立可视化辅助入口（与 AI 对话共享同一套 CLI 引擎）。 部署与写操作只作用于测试环境；线上环境一律只读，写入需要走官方审批流，页面不会提供入口。

🚀 合并 QA 分支并部署

选项目 → 选开发分支 → 合并进 QA 分支 → 推送 → 触发 Shipwright 构建 → 下发测试环境工作负载。合并全程在隔离 worktree 执行，不动你正在编辑的目录。

对应脚本：ci_deploy.js --merge-from

🩺 部署后自动验活

部署成功后自动拉取该服务近 10 分钟的测试环境容器日志，抓 ERROR 级别条目，一眼看出「部署完了服务到底活没活」。

对应脚本：test_log_query.js

🔍 日志检索（测试 / 生产）

按服务 + 关键词 + 时间窗 + 日志级别查日志。测试环境走大禹泳道容器日志，生产环境走 FAST/Kibana（严格只读）。

对应脚本：test_log_query.js / fast_query.js

⚙️ Apollo 配置速查与发布轨迹

查某服务在某环境的全量配置或按 key 关键字模糊搜；再按配置项追溯历次发布是谁、什么时候、把值从什么改成了什么。

对应脚本：apollo_query.js / apollo_history.js

🛠️ 测试环境写操作

Apollo 配置改值与发布、ES 文档改/删、Kafka 模拟投递、测试库 DML。全部强制「预检 → 确认」两步，未确认不写入。

对应脚本：apollo_modify.js / es_modify.js / kafka_send.js / test_mysql_query.js

🔑 凭据台账（18 项 · 切回自动同步）

一页看全 skill 依赖的全部 Cookie / Token（含 ONES）。点「刷新」先静默探活；需登录时在浏览器打开新标签页，登录完切回本页即自动单次同步落盘（零高频轮询）。

对应脚本：credential_relay.js（本地桥接 127.0.0.1:19526）

📜 历史任务回看

每次部署的完整日志都落盘在 ~/.shrimp/skills/live-inspector/deploy_jobs/，服务重启后仍能点开看失败原因。

入口：部署页右侧「最近任务」

安全边界

· 生产环境物理只读：任何写操作在后端就被拦截，页面不提供生产写入入口；
· 测试环境两步确认：所有写操作必须先「预检」看到 Diff，再点「确认提交」才真正写入；
· 部署合并隔离：合并冲突时严格失败并列出冲突文件，绝不自动改代码；QA 分支受保护时改走临时分支 + MR。

未手工登记 Git 地址的服务会自动扫描本机仓库或从 Shipwright 构建器反查并缓存
严格失败：出现冲突立即中止并列出冲突文件，不自动改代码、不推送、不部署。
